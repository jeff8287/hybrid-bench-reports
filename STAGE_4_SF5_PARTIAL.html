패턴 분석

Cache-friendly workloads (SF=5 더 잘 scale): - column_arith: per-row decimal arithmetic, no cross-row dependency → SIMD 가속 + cache stream - sort_values_multikey_mixed: SF=1 에서 P-cluster contention, SF=5 에서는 데이터당 비용 dominant → 분할 이득 ↑

Cache-bound workloads (SF=5 scaling 악화): - filter SF=1→SF=5 4.6x→2.1x: 단순 binary mask 인데 30M rows 의 mask + indexing 이 cache 압박 - merge_inner_singlekey SF=1→SF=5 3.3x→1.4x: orders.parquet 0.18GB hash table × 8 cores = 1.5GB > LLC 12MB 심각

→ Production model 의 raw_pe_ratio 가 SF 따라 다르게 추천해야 의미. (current API 는 SF 추론 후 lookup, OK)

3. Stage 06 model 영향 평가

기존 K=4 hybrid model 의 cluster 계수: - C1 (linear-scalable) α=0.96 — column_arith, filter, dt_year, str_endswith, groupby_agg 포함

SF=5 데이터로 fit 시 알파 변화: - column_arith, sort_values 는 그대로 또는 향상 - filter, merge_singlekey 는 SF=5 에서 α 더 낮음 (saturation 빠름)

→ Stage 06 의 단일 cluster (α, β, γ) 가 SF 평균 인데, SF=5 의 cache 효과는 cluster 내 분산을 키움. 이미 hybrid 모델의 outlier 처리 (read_parquet, groupby_agg_int_key) 가 본질적 IO/cache 케이스 처리. 잔여 보수적 영향 미미.
