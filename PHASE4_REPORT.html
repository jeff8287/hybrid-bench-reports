Phase 4+5a Report — PCCS Source-Obliviousness Validation (FAIL with quantified bias)

Date: 2026-05-27 Predecessor: Phase 3 REPORT (17 APIs, best pccs_k3 6.06% MAPE under Bandit pressure) Status: Hypothesis falsified, but bias direction quantified — actionable for predictive scheduling

TL;DR

PCCS source-obliviousness 가설 FAIL on Intel Lunar Lake real pandas workloads:

  1. Phase 4 (245 cells across 40 setup configurations, no emon): 60/245 retained for verdict, mean error 34.0% — INCONCLUSIVE 표면적이지만 directional FAIL.
  2. Phase 5a (emon-measured aggregate BW, 8 setups): saturation 직접 관찰 (N=2 ratio 0.99 → N=8 ratio 0.60). aggregate BW 정확히 측정해도 25.7% mean error.
  3. Systematic bias: Bandit consistently overestimates real workload contention by ~38-50% (real_sd ≈ predicted_sd × 0.5-0.6).
  4. Root cause (Architect's antithesis confirmed): Bandit 의 1.4 GB working set 이 real workload 의 42 MB 보다 cache eviction 훨씬 강함. 같은 aggregate DRAM BW 라도 cache pressure 다름.

→ Phase 3 의 Bandit-trained 모델 (6.06% MAPE) 은 real co-run 에서 slowdown overestimate. Real-world predictive scheduling 에 corrective factor 필요 OR cache-aware model 필요.

1. Research question

측정된 self_BW = Y GB/s 인 실제 pandas API generator pool 이 victim API V 에 주는 slowdown 이, 같은 aggregate BW Y GB/s 압력을 주는 Bandit 의 slowdown 과 같은가?

Hypothesis H1 (PCCS source-obliviousness): real_slowdown(V, generator_pool) ≈ bandit_curve(V, core)(Σ self_BW(generators)).

PASS gate (pre-registered): mean<10%, p90<20%, max<40%, retained ≥ 80%.

5. Root cause analysis

5.1 Architect's antithesis confirmed

In v1 review, Architect flagged:

Real generators × 6 MB partition each (~42 MB total working set) versus 7 Bandit threads × 200 MB stream (1.4 GB) creates a fundamentally different cache hierarchy state at matched ext_bw.

Phase 4+5a confirms this: - Same aggregate DRAM BW → different victim slowdown (Bandit gives more, real gives less) - Reason: Bandit 의 200MB stream 이 L2/L3 cache 를 완전히 evict → victim 의 cache state degrade → victim instructions per cycle ↓ - Real workloads (lineitem partition ~6MB) 은 cache 에 들어가 → victim 의 cache 상대적 유지

5.2 Implication for Phase 3 결론

Phase 3 의 6.06% MAPE pccs_k3 모델은 Bandit data 에 정확. 하지만: - Real co-run 에서 systematic overestimate (~50% bias on Bandit predicted slowdown) - 만약 절대 정확도가 필요 없고 ordering 만 필요하면 (P vs E core 선택) → 사용 가능 (안전 방향) - 만약 정확한 slowdown 필요 (deadline-driven scheduling) → corrective factor 또는 cache-aware model 필요
