BW-Aware Latency Prediction on Intel Lunar Lake Hybrid CPU — Final Report

Date: 2026-05-28 Project: dev/260519_bw_aware_prediction/ Platform: Intel Core Ultra 7 256V (Lunar Lake), 4 P-core + 4 E-core, LPDDR5X-8533 peak 136.5 GB/s Period: 6 phases over 9 days

Executive Summary

Research Question

Can pandas API latency under co-run contention be predicted using only bandwidth signals (no cache counters, no admin)? On Intel Lunar Lake hybrid CPU, what is the production-deployable accuracy?

Headline Results

Phase Method MAPE Note
Phase 3 Bandit-trained pccs_k3 (in-sample) 6.06% clean synthetic contention
Phase 4 Real co-run (no correction) 34.0% reality check — Bandit overestimates
Phase 5b Bounded Bandit (cache footprint match) 26.3% cache = 30% of bias
Phase 6 self_BW-aware correction (M5) 18.5% ⭐ production-ready

Production-ready model (no cache, no admin)

real_slowdown ≈ bandit_predicted × correction(victim_self_BW, agg_BW, pool_size)

where correction = 0.77 + 0.0016 × victim_self_BW
                       − 0.0097 × aggregate_self_BW
                       + 0.066 × pool_size

Mean LOO-API MAPE: 18.5% (Phase 4 의 34% → 18% 절반으로 감소).

Headline Findings

  1. PCCS source-obliviousness 가 깨짐: Bandit 과 real workload 가 같은 aggregate BW 에서도 다른 victim slowdown (Bandit overestimates ~2x).
  2. Cache footprint 가 부분 cause (~30%), 나머지 ~70% 는 prefetcher / access pattern / uncore traffic 추정.
  3. Memory BW saturates in multi-thread: 1 → 8 cores 에서 ratio 1.0 → 0.55.
  4. Production model 정확도: cache counters 없이 self_BW + pool_size 만으로 18.5% — 충분히 actionable (scheduler decisions).

1. Research Goals

원래 가설 (project start):

Bandwidth 측정 (self_BW + external pressure) 만으로 각 pandas API 의 co-run latency 를 충분히 정확하게 예측할 수 있다.

이 가설을 Intel Lunar Lake 의 hybrid CPU (P+E) 에서 검증.

Why this matters

  • Hybrid CPU 의 scheduling 결정 (어떤 작업 P/E 코어로) 은 co-run contention 예측에 의존
  • Cache miss counters 는 정확하지만 측정 overhead 큼 (특히 production)
  • BW 측정 (RAPL DRAM, emon CAS) 만으로 가능하다면 lightweight production model 가능

2. Phase 별 Progress

Phase 1-2: 초기 8-API BW model

  • Setup: 8 pandas APIs × Bandit (synthetic stress), PCCS-style slowdown curve
  • Best: pccs_k2 (self_BW 2-region) 12.26% MAPE
  • Limit: self_BW range 좁음 (5-17 GB/s) → PCCS formula 16.98% FAIL

Phase 3: 17 APIs (+9 NEW)

  • 추가: read_parquet_* (IO), filter variants, groupby cardinality 3종, merge_left_outer
  • 새 발견:
  • groupby_agg_int_key self_BW = 0.34 GB/s (200K hash in L2 cache, compute-bound)

  • Range 확장: 0.34 - 20.46 GB/s (50× wider on low end)
  • Best: pccs_k3 (self_BW 3-region) 6.06% MAPE (LOO-API CV, in-sample 의 의미)
  • PCCS formula 회복: 16.98% → 11.02% (wider self_BW range 덕분)

→ Phase 3 Report

Phase 4: Real co-run validation (FAIL)

  • Question: Bandit-trained model 이 real pandas workload 동시 실행에서 작동하는가?
  • Setup: 40 setups × 8-core parallel, 245 cells (homo / pair / hetero / sparse)
  • Result:
  • 60/245 retained (76% extrapolated past Phase 3 Bandit max BW)
  • retained: mean 34% error
  • real_slowdown < predicted_slowdown 일관 → Bandit overestimates by ~2x
  • VERDICT: INCONCLUSIVE 표면, directional FAIL

Phase 5a: emon aggregate BW (BW saturation 발견)

  • Setup: 8 setups × system-wide emon, real workload pool
  • 결과 (5/8 OK):
  • N=2: ratio measured/predicted = 0.99 (no saturation)
  • N=8: ratio = 0.60 (heavy saturation)
  • 결론: Σ self_BW 가 1.67× overestimate at N=8
  • Corrected (measured BW 로 prediction): 여전히 25.7% mean error → saturation 만으로는 해결 안 됨

→ Phase 4+5a Report

Phase 5b: Bounded Bandit (cache footprint test)

  • Hypothesis: Bandit (200MB stream × 7 threads = 1.4GB) vs real (6MB × 7 = 42MB) 의 cache footprint 차이가 cause?
  • Setup: Phase 3 와 정확히 같은 protocol, Bandit ARR_BYTES = 200MB → 6 MB (13h 41min sweep)
  • Result:
  • Phase 4 60 cells re-predict with bounded curve: mean error 34% → 26.3% (−7.7pp)
  • 305 non-idle cells: bandit_orig vs bandit_bounded 거의 동일 (ratio 0.93) — DRAM at K=K0 saturates regardless
  • 결론: Cache footprint = 부분 cause (~30%)
  • 나머지 ~70% bias: prefetcher? access pattern? uncore traffic?

60 retained cells 의 bias 분석:

  • 7 새 setups 측정 (Phase 5a 5 + Phase 5c 7 = 12 OK)
  • New saturation curve: ratio(N) = 1.28 / (1 + 0.19 × (N-1)) N=1: 1.28 · N=4: 0.81 · N=8: 0.55 (이전 fit N=8: 0.65 → 더 강한 saturation)
  • Setup 9 (8 × filter homo): ratio 0.16 — 극단 saturation (cache contention 으로 8 cores ≈ 1 core BW)

  • M5 formula (production): ratio = 0.7711 + 0.0016 × victim_self_BW − 0.0097 × aggregate_self_BW + 0.0662 × pool_size

3. Headline Findings

3.1 PCCS source-obliviousness 가 production 에선 깨짐

원 가정 (Wang et al. MICRO'21): aggregate external BW 가 같으면 contention source 와 무관하게 victim slowdown 같음.

Reality (Phase 4+5a): Same aggregate BW (measured) 라도 Bandit vs real workload 가 ~25-35% 다른 slowdown.

3.2 Cause decomposition

Cause 기여 Evidence
Σ self_BW overestimate (linear sum 가정) ~10pp Phase 5a/5c saturation measurement
Cache footprint mismatch (1.4GB vs 42MB) ~8pp Phase 5b bounded Bandit experiment
나머지 unknown: prefetcher / access pattern / uncore ~16-18pp residual after above

3.3 Bias structure (production formula 근거)

  • Multiplicative form 이 additive 보다 일관 (CV 0.22 vs 0.72)
  • Compute-bound API (low self_BW) 가 가장 큰 overestimate
  • Pool size 클수록 약간 더 overestimate (saturation 효과 가중)

3.4 Memory BW saturates aggressively at high N

N=1: ratio 1.0   (no saturation)
N=4: ratio 0.81  (mild)
N=8: ratio 0.55  (heavy)

이론적 LPDDR5X peak 136.5 GB/s → 실측 sustained ≈ 45-50 GB/s.

4. Production Recommendation

Model formula

def predict_real_slowdown(victim_api, victim_core_label,
                          generators_list,
                          phase3_bandit_curve, phase3_self_bw):
    """
    victim_api: pandas API name (one of 17)
    victim_core_label: "P1" or "E1"
    generators_list: [(api_name, core_label), ...]
    Returns: predicted real_slowdown
    """
    # Phase 3 measured values
    sbw_v = phase3_self_bw[(victim_api, victim_core_label)]

    # Aggregate Σ self_BW (no saturation needed - small bias if N<5)
    agg_bw = sum(phase3_self_bw[(g, c)] for g, c in generators_list)

    pool_size = len(generators_list)

    # Phase 3 Bandit prediction
    bandit_pred = phase3_bandit_curve[(victim_api, victim_core_label)](agg_bw)

    # Phase 6 M5 correction
    correction = (0.7711
                  + 0.0016 * sbw_v
                  - 0.0097 * agg_bw
                  + 0.0662 * pool_size)

    return bandit_pred * correction

Inputs needed

Input Source One-time cost
self_BW(api, core) Phase 3 emon (admin, 17 APIs × 2 cores) ~3 hours admin shell
bandit_curve(api, core) Phase 3 Bandit sweep ~18 hours (no admin)
Per-prediction: pool composition runtime info free

No cache counters required. No admin at prediction time.

Expected accuracy

  • Mean MAPE 18-20% on real co-runs (LOO-API CV)
  • Direction: conservative (over-estimate) — safer for scheduling decisions
  • Worst case: compute-bound APIs (groupby_agg_int_key) up to 70% error → scheduler should treat as "safe to co-locate"
  • Best case: BW-bound APIs (merge_inner_*, filter) ~10% error

5. Limitations + Future Work

5.1 Sample size limits

60 retained Phase 4 cells 가 model fit 의 한계. - 245 cells 다 사용 시 saturation noise 증가 → MAPE 더 안 좋음 (37%) - 더 많은 setups 필요 → next iteration

7. ADR (Architecture Decision Record)

Decision: Adopt Phase 6 M5 correction model (60 retained cells, multivariate linear) for production prediction.

Drivers: - Best mean LOO-API MAPE among tested approaches (18.5%) - Uses only self_BW (no cache counters, no admin at runtime) - Simple closed-form (4-term linear) — implementable in any scheduler - Direction conservative (overestimate) — safe scheduling fallback

Alternatives rejected: - Direct regression on 245 cells (37.8%) — saturation noise - Hybrid saturation + Bandit + correction (57.5%) — oversaturation noise - Phase 3 model alone (6% in-sample, 34% real) — overestimates 2× - Bounded Bandit + no correction (26%) — partial fix, still high error

Consequences: - (+) Production-ready without admin or cache counters - (+) Documented bias direction (conservative) - (−) ~70% of bias unexplained — future research opportunity - (−) Phase 3's "6.06%" headline is in-sample only, real-world ~18-20%

Follow-ups: - Random-access Bandit kernel (memory pattern test) - Prefetcher disable (BIOS) for 1 control setup - Uncore counter sweep (admin emon) - Real production deployment validation

Final report. Project closed at commit bb402a1.
