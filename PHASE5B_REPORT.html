Phase 5b Report — Bounded Bandit Experiment (cache footprint partial cause)

Date: 2026-05-27 Predecessor: Phase 4+5a REPORT (PCCS FAIL, 25.7% mean error after BW correction) Status: cache footprint = partial contributor (~30% of total bias). Other factors remain to be identified.

TL;DR

Bounded Bandit (6 MB array per thread, matches real workload working set) sweep on Phase 3 protocol:

Method mean MAPE Δ vs Phase 4
Phase 4 (orig 200MB Bandit) 34.00% —
Phase 5b (bounded 6MB Bandit) 26.33% −7.7pp
PASS gate <10% FAIL still

→ Cache footprint hypothesis (Architect's antithesis) partially confirmed: - ~30% of the 25-35% bias comes from cache differences (~8pp absolute) - ~70% of the bias from other unknown causes

Bandit slowdown 자체는 array size invariant at K=K0 regime: 7-thread × 6MB (42 MB) > L3 12MB 면 어차피 DRAM 압력 saturate. Only the cache-friendly region (low BW) shows small differences.

1. Design

Phase 3 와 정확히 같은 protocol, ARR_BYTES 만 변경:

# Original Phase 3
ARR_BYTES = 200 * 1024 * 1024   # 200 MB / thread (1.4 GB total)

# Bounded (NEW)
ARR_BYTES = 6 * 1024 * 1024     # 6 MB / thread (42 MB total)
                                # matches lineitem partition working set

Identical Phase 3 sweep otherwise: - 17 APIs × 2 cores (P1, E1) - 10 K levels (idle → K0) - 13 reps per cell (3 warmup + 10 measure) - 7-thread Bandit on non-victim cores

Sweep wall: 13h 41m (no admin, detach-run).

2. Results

2.1 Slowdown curve differences (orig vs bounded)

Per (V, core, K) comparison across 305 non-idle cells:

sd_diff (orig - bounded): mean +0.136, median +0.090
ratio (bounded / orig):   mean 0.931, median 0.946

→ Bounded gives slightly less slowdown but only marginally (mean 7% less).

Key observation: At K=K0 (max BW), curves nearly identical. Differences mostly in K100-K500 region (mid-BW), where cache state matters more.

3. Interpretation

3.1 Cache footprint contributes ~30%

(34.0% − 26.3%) / (34.0% − ideal 0%) ≈ 23% of total bias is attributable to cache footprint. The remaining ~77% has other causes.

3.2 Bandit kernel array size is mostly invariant at high BW

At K=K0 (max BW, peak DRAM 압력): bandit_curve_orig ≈ bandit_curve_bounded - Reason: 7 threads × 6 MB = 42 MB > Lunar Lake L3 12 MB → cache miss regardless - DRAM access rate determined by kernel memory access pattern (1 read + 1 write per K compute), not by array size

At mid BW (K100-K500), small differences appear. Likely cache hit rate variations.

3.3 Remaining cause candidates

Cause How to test
Memory access pattern: Bandit = sequential stream (prefetcher friendly), real = mixed patterns New experiment with random-access Bandit kernel
Prefetcher behavior: Bandit triggers HW prefetcher aggressively, real workloads less so Disable prefetcher (BIOS) and re-measure 1 setup
Ring/uncore traffic: same DRAM BW but different ring traffic patterns (request-response sizes) emon ring counters
Cache associativity / TLB: Bandit hits different cache sets than real (alignment) Random array start offset
Compute mix: Bandit's 50% compute (K=K100) vs real's varying compute density Mix Bandit + pandas operations as generator

5. Implications

5.1 For Phase 3 model accuracy

Phase 3's 6.06% MAPE pccs_k3 model (Bandit-trained 200 MB): - Real co-run actual error: 26-34% (FAR worse than 6.06%) - Bandit-correction (factor ~0.5) addresses systematic component - Bounded Bandit alone reduces error by ~25% — not enough

5.2 For predictive scheduling

Phase 3 model systematically overestimates real workload slowdown by ~2x. Implications: - Conservative (safe) direction: scheduler avoids P-core when it should - Sub-optimal: P-core may actually be fine, missing throughput opportunity - Pre-deployment: apply ~0.4-0.5 correction factor

5.3 For PCCS theory

PCCS's source-obliviousness assumption (extended to real workloads) is not just about cache — there's a larger second cause. Possible directions: - Memory access pattern matters - Hardware prefetcher behavior - Uncore queue depth / ring saturation

6. ADR

Decision: Document cache footprint as partial cause of PCCS source-oblivious FAIL. Don't claim cache solves it; ~70% of bias remains.

Drivers: - Pre-registered FAIL gate didn't pass - Quantified partial improvement (7-8pp) - Identified actionable next direction (random-access Bandit, prefetcher tests)

Evidence: - Phase 4 with orig curve: mean 34% error - Phase 5b with bounded curve: mean 26% error - Improvement Δ = 8pp - Bandit curves only differ at mid-BW, near-identical at K=K0

Consequences: - (+) Architect's antithesis 부분 검증 (한 가지 factor 확정) - (+) 후속 실험 방향 좁힘 (access pattern, prefetcher, uncore) - (−) Single-cause hypothesis 부정 (decomposition 필요)

Follow-ups: - Random-access Bandit kernel (mid-cost, addresses 25% candidate) - Prefetcher disable test (low cost, 1 BIOS setting + 1 setup re-measure) - Uncore counter sweep (admin emon, ring traffic) - For Phase 3 model: use ~0.5 correction factor 적용 in production
